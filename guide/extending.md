# 가이드 확장 규칙 (기능 추가 시 문서 작성법)

새 기능을 개발할 때마다 공개 가이드를 함께 갱신한다. `docs/` 변경은
main push 시 GitHub Action(`deploy-docs.yml`)이 자동으로
`moda-grid-releases` 공개 레포에 배포한다 — 별도 배포 작업은 없다.

## 기능 추가 시 체크리스트

1. **기능 문서 작성/갱신**
   - 기존 기능 개선 → 해당 [features/](features/) 문서를 수정한다.
   - 새 기능 카테고리 → `docs/guide/features/<기능명>.md`를 새로 만들고
     [guide/README.md](README.md)의 "기능별 가이드" 표에 행을 추가한다.
   - 새 플랫폼 어댑터 → `docs/guide/platforms/<프레임워크>.md`를 만들고
     목차 표에 추가한다.
2. **개발자 문서 갱신** — API/타입이 바뀌면 상위 `docs/02-core-api.md`,
   `03-framework-adapters.md`, `05-usage-guide.md`도 함께 갱신한다.
   `ColumnDef`/`GridOptions` 스키마가 바뀌면 05 문서 상단 타입 블록도 갱신.
3. **커밋에 문서 포함** — 기능 코드와 문서 변경을 같은 PR/커밋에 넣는다.
   문서가 빠진 기능 PR은 완료로 보지 않는다.

## 기능 문서 템플릿

```md
# 기능명 (English Name)

한두 줄 개요 — 무엇을 하는 기능인지.

## 설정
(컬럼/옵션 선언 예시)

## 사용자 조작 (DataGrid 기본 동작)
(사용자가 화면에서 하는 조작 → 동작 표)

## 코어 API
(메서드 표 또는 코드 블록)

## 어댑터 렌더링
(어댑터가 자동으로 해주는 것, 관련 CSS 클래스)

## 동작 규칙 / 주의사항
(제약, 다른 기능과의 상호작용, 기본값)

## 관련 스냅샷 필드
```

## 작성 규칙

- **코어 API 중심** — 4개 어댑터는 동작이 동일하므로 코어 API + 공통 UI
  동작을 먼저 쓰고, 프레임워크별 차이가 있을 때만 플랫폼 절을 추가한다.
- **복사 가능한 예시** — 코드는 바로 붙여 쓸 수 있게 완결된 형태로.
- **스냅샷 필드 명시** — `snapshot.xxx`로 읽는 상태는 반드시 필드명을 적는다.
- **CSS 클래스 명시** — 어댑터가 붙이는 `.mg-*` 클래스는 커스텀 스타일링의
  진입점이므로 빼놓지 않는다.
- **한국어** — 본 가이드는 한국어로 작성한다 (코드 주석·식별자는 영어).

## AI 에이전트용 요약

기능 PR을 작성하는 AI는 다음을 수행한다:

1. `packages/core/src` 또는 어댑터 변경 사항에서 사용자 노출 기능을 식별
2. 위 템플릿에 맞춰 `docs/guide/features/*.md` 생성 또는 기존 문서 수정
3. `docs/guide/README.md` 목차 표에 행 추가 (새 파일인 경우)
4. `docs/05-usage-guide.md`의 "기능 명세" 섹션에도 항목 추가
5. `ColumnDef`/`GridOptions` 변경 시 05 문서 상단 타입 블록 갱신
6. 코드와 같은 커밋으로 포함 → push 시 자동 배포
